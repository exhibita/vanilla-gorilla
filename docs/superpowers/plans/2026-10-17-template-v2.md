# Vanilla Gorilla Template Version 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make template version 2 of Vanilla Gorilla (drafts, `images:` galleries, version marker, license) and test it on one new scratch site. This is step 1 of the Gorilla To Go (GTG) build order.

**Architecture:** All changes are in this repository (`vanilla-gorilla`). `build.js` gets two small features: it skips pages with `draft: true`, and it fills a new gallery skeleton from an `images:` frontmatter list. Tests are black-box: each test builds a small site in a temp directory with the real `build.js`, templates and skeletons, then reads `dist/`.

**Tech Stack:** Node.js ES modules, `cheerio`, `gray-matter`, `marked` (already dependencies). Tests use the built-in `node:test` and `node:assert`. No new dependencies.

**Spec:** `../gorilla-to-go/docs/mvp-plan.md` sections 3, 4 and 8 (step 1), and `../gorilla-to-go/docs/decisions.md` (decisions 6, 8, 9, 17 and the "Test site" note). Background: `../gorilla-to-go/docs/vanilla-gorilla-notes.md`.

## Global Constraints

- Version marker: `"vanillaGorilla": { "templateVersion": 2 }` in `package.json`. Not in `config.json` (decision 9).
- License field: `"license": "AGPL-3.0-or-later"` in `package.json` (mvp-plan section 3, decision 17).
- Do not change the `"version"` field in `package.json`. The template version is separate.
- Drafts: the build skips a page that has `draft: true` in its frontmatter (mvp-plan section 3).
- Galleries: an `images:` list in the frontmatter, with a path, alt text and caption for each image. The gallery skeleton makes the grid and the lightbox from this list (mvp-plan section 3).
- Image entry shape (contract for GTG steps 7 and 8): `{ path, alt, caption }`. `path` is relative to `src/` and starts with `./`, for example `./images/gallery/<slug>/photo.jpg`.
- Images for a page go in `src/images/<type>/<slug>/` (mvp-plan section 7).
- No client-side JavaScript in the gallery. The lightbox stays CSS-only (`:target`).
- Do not change `.github/workflows/`. A template upgrade that changes workflows needs an extra token permission (`docs/future.md` in GTG).
- Existing hand-built HTML pages and HTML galleries must build as before.
- Each push to `main` deploys this repository's own demo site (`pages.yml`, `deploy.yml`). Work on the branch `template-v2`. Merge only after review (`.github/CONTRIBUTING.md`).
- Agent rules in `.agents/rules/agent-guidelines.md` apply: minimum code, surgical changes, match the existing style (4-space indent, single quotes, semicolons in `build.js`), run `npm run build` before you finish.
- New documentation uses the ASD STE100 style: direct sentences, one action for each procedural step.
- Tests need Node.js 22 or later (`node --test` with a glob). The CI build stays on Node 20 and does not run tests.

## Review Focus

1. **Draft value typed as a string** (`draft: "true"`, from a hand edit): a person expects the page to stay private. The build must treat the string `"true"` (any case) as a draft. Test: Task 3, `quoted-draft` fixture.
2. **A draft that is the newest post**: a person expects no trace of it on the live site. The build must keep it out of the blog index, RSS, sitemap, recent posts and the prev/next links of other posts. Test: Task 3, `secret-post` fixture is newer than `live-post`.
3. **A caption or alt text with `&`, `<` or `"`**: a person expects the text to show as typed, and the page must not break. The build must escape it. Test: Task 4, caption `Fish & <Chips>`.
4. **A bad `images:` entry** (no `path`, or `images:` is not a list): a person expects the other images to show and the build to succeed. The build must skip the entry with a warning. Test: Task 4, entry with no path and the `bad-list` fixture.
5. **A gallery with one image or no images**: a person expects a working page. With one image there are no prev/next arrows. With no images the page shows only the title and text. Test: Task 4, `one-photo` and `empty-gallery` fixtures.

import { spawnSync } from 'node:child_process';
import fs from 'node:fs';
import os from 'node:os';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

export const ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..');
const BUILD_JS = path.join(ROOT, 'build.js');

// Build a throwaway site in a temp directory and return helpers to inspect it.
// pages maps a path relative to src/ to the file content.
// fullSrc copies the whole template src/; otherwise only templates/ and skeletons/ are copied.
export function buildSite(pages = {}, { fullSrc = false } = {}) {
    const dir = fs.mkdtempSync(path.join(os.tmpdir(), 'vg-test-'));
    const src = path.join(dir, 'src');
    const copy = sub => fs.cpSync(path.join(ROOT, 'src', sub), path.join(src, sub), { recursive: true });

    if (fullSrc) {
        copy('');
    } else {
        copy('templates');
        copy('skeletons');
    }

    for (const [relativePath, content] of Object.entries(pages)) {
        const file = path.join(src, relativePath);
        fs.mkdirSync(path.dirname(file), { recursive: true });
        fs.writeFileSync(file, content, 'utf8');
    }

    const result = spawnSync(process.execPath, [BUILD_JS], { cwd: dir, encoding: 'utf8' });

    return {
        dir,
        status: result.status,
        output: `${result.stdout}${result.stderr}`,
        read: relativePath => fs.readFileSync(path.join(dir, 'dist', relativePath), 'utf8'),
        exists: relativePath => fs.existsSync(path.join(dir, 'dist', relativePath)),
        readSrc: relativePath => fs.readFileSync(path.join(src, relativePath), 'utf8'),
        cleanup: () => fs.rmSync(dir, { recursive: true, force: true })
    };
}
```

// Make a gallery image path start with "./" so adjustDocumentLinks can fix it for the page depth.
function relativeImagePath(imagePath) {
    if (/^(\.{0,2}\/|[a-z][a-z0-9+.-]*:)/i.test(imagePath)) return imagePath;
    return `./${imagePath}`;
}

// Read the "images:" front matter list. Return the usable entries as { src, alt, caption }.
function galleryImages(frontmatter, relativePath) {
    if (frontmatter.images === undefined) return [];
    if (!Array.isArray(frontmatter.images)) {
        console.warn(`Warning: ${relativePath}: "images" must be a list; ignoring it.`);
        return [];
    }

    const images = [];
    frontmatter.images.forEach((image, i) => {
        if (!image || typeof image.path !== 'string' || !image.path.trim()) {
            console.warn(`Warning: ${relativePath}: images[${i}] has no "path"; skipping it.`);
            return;
        }
        images.push({
            src: relativeImagePath(image.path.trim()),
            alt: String(image.alt ?? image.caption ?? ''),
            caption: image.caption == null ? '' : String(image.caption)
        });
    });
    return images;
}

// Fill the gallery skeleton's #gallery grid and #gallery-lightboxes with CSS-only lightbox markup.
function renderGallery($, images) {
    const count = images.length;

    const items = images.map((image, i) => {
        const captionHtml = image.caption
            ? `\n            <div class="gallery-caption">${escapeHtml(image.caption)}</div>`
            : '';
        return `    <div class="gallery-item">
        <a href="#img${i + 1}">
            <img src="${escapeHtml(image.src)}" alt="${escapeHtml(image.alt)}">${captionHtml}
        </a>
    </div>`;
    }).join('\n');

    const lightboxes = images.map((image, i) => {
        const prev = ((i - 1 + count) % count) + 1;
        const next = ((i + 1) % count) + 1;
        const descHtml = image.caption
            ? `\n        <div class="lightbox-desc">${escapeHtml(image.caption)}</div>`
            : '';
        const navHtml = count > 1
            ? `\n        <a class="lightbox-nav lightbox-prev" href="#img${prev}">&lsaquo;</a>\n        <a class="lightbox-nav lightbox-next" href="#img${next}">&rsaquo;</a>`
            : '';
        return `<div class="lightbox-target" id="img${i + 1}">
    <div class="lightbox-content">
        <img src="${escapeHtml(image.src)}" alt="${escapeHtml(image.alt)}">${descHtml}
        <a class="lightbox-close" href="#gallery">&times;</a>${navHtml}
    </div>
</div>`;
    }).join('\n');

    $('#gallery').html(`\n${items}\n`);
    $('#gallery-lightboxes').html(`\n${lightboxes}\n`);
}
```

## Drafts

Add `draft: true` to the front matter of a Markdown page:

```yaml
---
title: My next post
date: 2026-10-17
draft: true
---
```

The build does not publish the page. The page is not in the blog index, the RSS feed, the sitemap or the gallery index. To publish the page, remove the `draft` line.

Note: images in `src/images/` are always copied to the site, also for a draft page.

## Galleries

A gallery is a Markdown file at `src/gallery/<slug>/index.md` with `skeleton: gallery` and an `images:` list:

```yaml
---
title: Beach trip
date: 2026-10-17
description: Photos from the beach.
skeleton: gallery
images:
  - path: ./images/gallery/beach-trip/waves.jpg
    alt: Waves on the sand
    caption: Morning waves
---

Text above the photos.
```

- `path`: the image path from `src/`. Start it with `./`. Put the images in `src/images/gallery/<slug>/`.
- `alt`: the text for screen readers. If there is no `alt`, the build uses the caption.

The first image is the cover on the gallery index. To use a different cover, add `cover: ./images/...`.

| `#gallery-lightboxes` | The lightbox for each image |
